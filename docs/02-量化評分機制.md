# 02 · 量化評分機制（資料集與演算法）

> **English summary**
> This is the core of the project: how a title becomes a number. Breakout Index v0.1 is a
> five-dimension weighted score (reach, quality, buzz, momentum, crossover), each mapped to an
> absolute 0–100 scale from a named raw signal, then shrunk toward 50 by sample size. The dataset
> (`app/public/data/works.json`) is versioned, validated in CI, and every record carries a data status
> (`measured` / `estimated` / `illustrative`), a 90% interval, and machine-checkable sources.
> The model is a **relative heat index**, not a quality verdict and not a causal claim. v0.2 adds
> cohort-normalised z-scores, multi-source Bayesian pooling and Shapley-style attribution.

---

## 中文

### 1. 設計目標

| 目標 | 具體要求 |
|---|---|
| 可比較 | 四種媒介（短劇／動漫／小說／電影）能放在同一把尺上 |
| 可解釋 | 每個分數都能拆成「維度 × 權重」的貢獻 |
| 可追溯 | 每個數字都有來源、資料截止日、資料狀態 |
| 可重現 | 任何人重跑 `scripts/` 都能得到同一個結果 |
| 誠實 | 樣本不足時給區間與信心等級，不給虛假的單點排名 |

**明確不做**：不宣稱分數是「絕對品質」，不做因果歸因（「因為劇情好所以火」），不把平台後台指標假裝成公開資料。

### 2. 分數的語義

```
0–49   低於同類基準線
50      同類基準線（中性）
60–69   值得看
70–79   強檔
80–87   爆款
88–100  現象級
```

分數是**相對熱度**：92 分不代表「比 80 分好看 12%」，而是「在同類作品中，綜合熱度的相對位置更靠前」。

### 3. v0.1 模型（目前實作）

#### 3.1 五個維度

| 維度 | 代號 | 衡量什麼 | 動漫的原始訊號（實測） | 短劇／小說／電影的原始訊號（估算） |
|---|---|---|---|---|
| 熱度規模 | `reach` | 有多少人接觸到 | AniList `popularity`（加入清單人數） | 播放量、票房、在讀人數 |
| 口碑品質 | `quality` | 評價如何（貝氏收縮後） | AniList `meanScore` + 評分人數 | 豆瓣／平台評分、獎項、媒體評價 |
| 討論聲量 | `buzz` | 社群參與度 | 評分人數、收藏率 | 熱搜、話題量、二創量 |
| 當下動能 | `momentum` | 近 7–30 日變化速度 | AniList `trending` | 上線初期的榜單斜率、熱度曲線 |
| 破圈能力 | `crossover` | 相對同題材基準線的超出幅度 | 相對同主要類型 `popularity` 中位數的超出量 | 是否吸引核心圈層外的觀眾 |

#### 3.2 正規化（絕對刻度，非批次排名）

所有原始訊號先轉成 0–100 的絕對刻度，公式中的常數是「校準參數」，公開於此：

```text
reach      = 100 · (log10(pop) − 3.3) / (5.9 − 3.3)
quality    = 100 · (WR − 58) / (90 − 58)
             WR = (n · S + 500 · 78) / (n + 500)        # 貝氏收縮，m = 500，C = 78
buzz       = 100 · (log10(n) − 3.4) / (5.9 − 3.4)
momentum   = 100 · (log10(trending + 1) − 1.3) / (2.7 − 1.3)
crossover  = 100 · (excess + 0.5) / (0.8 + 0.5)
             excess = log10(pop) − median(log10(pop) | 同主要類型)
```

- 取對數：計數型指標（人數、播放）長尾極重，log 後才不會被少數巨頭主導。
- 貝氏收縮：`n` 是評分人數；新作或小眾作會被拉向 78 分，避免「3 個人打 9.8 分」奪冠。
- 破圈用「同題材中位數」當基準線：控制題材紅利，衡量「超出同類多少」。

#### 3.3 加權與信心收縮

```text
Hit_raw = Σ_d  w[medium][d] · dim_d
Hit     = 50 + (Hit_raw − 50) × λ
λ       = max(0.93, n / (n + 600))        # 僅動漫；n = AniList 評分人數
```

短劇／小說／電影為編輯估算，**不做二次收縮**（避免雙重懲罰），改用較寬的區間表達不確定性：

```text
CI90 = Hit ± δ
δ    = clamp(2160 / √n, 0.8, 6)    # 動漫，依評分樣本量
δ    = 5.5                          # estimated 資料
```

#### 3.4 權重（v0.1）

| 媒介 | 熱度 | 口碑 | 討論 | 動能 | 破圈 |
|---|---|---|---|---|---|
| 短劇 | 26% | 14% | 22% | 20% | 18% |
| 動漫 | 28% | 26% | 16% | 15% | 15% |
| 小說 | 24% | 24% | 20% | 17% | 15% |
| 電影 | 30% | 26% | 16% | 14% | 14% |

設計邏輯：短劇重「討論 + 破圈」（社群傳播是主要增長引擎）；動漫重「口碑」（社群評分成熟、樣本大）；電影重「熱度」（票房是硬指標）。

#### 3.5 貢獻度分解（瀑布圖）

```text
contribution_d = w[medium][d] · (dim_d − 50) · λ
Σ contribution_d = Hit − 50
```

網站作品頁的「為什麼火」瀑布圖就是這條式子：以 50 為基準，每一維往右是加分、往左是扣分，加總等於破圈指數。

### 4. 資料字典（`works.json`）

| 欄位 | 型別 | 說明 | 來源 |
|---|---|---|---|
| `id` | string | 唯一識別碼（`anilist-<id>` / `sd-*` / `nv-*` / `fl-*`） | 管線產生 |
| `medium` | enum | `shortdrama` / `anime` / `novel` / `film` | 編輯 |
| `title.zh` / `title.en` / `title.native` | string | 繁中名／英文名／原文名 | 編輯／AniList |
| `year` | number | 上線或出版年份 | 來源 |
| `region` | string | `CN` / `JP` / `HK` / `US` … | 編輯 |
| `platform` | string? | 平台或製作公司 | 來源 |
| `genres` | string[] | 標準化類型（英文 key，前端翻譯） | AniList／編輯 |
| `tags` | `{zh,en}[]` | 標籤（雙語） | AniList／編輯 |
| `episodes` / `episodeMinutes` | number? | 集數／單集長度（小說為章數） | 來源 |
| `synopsis` | `{zh,en}` | 一句話簡介（雙語） | 編輯／自動生成 |
| `dims` | `{reach,quality,buzz,momentum,crossover}` | 五維 0–100 | 模型計算 |
| `hitScore` | number | 破圈指數 | 模型計算 |
| `contributions` | `{key,points}[]` | 各維貢獻（相對 50） | 模型計算 |
| `ci` | `[low, high]` | 90% 區間 | 模型計算 |
| `confidence` | enum | `high` / `medium` / `low` | 依樣本量 |
| `heatCurve` | number[12]? | 週熱度（示範） | 編輯 |
| `scoreDistribution` | `{score,amount}[]`? | 評分分布（實測） | AniList |
| `drivers` | `{text:{zh,en}, source?}[]` | 質性驅動因素（非模型輸出） | 編輯 |
| `provenance.status` | enum | `measured` / `estimated` / `illustrative` | 規則 |
| `provenance.sources` | `{name,url,note}[]` | 來源清單（必填） | 編輯／管線 |
| `provenance.note` | `{zh,en}` | 口徑說明 | 編輯 |

**資料狀態規則**：
- `measured`：來自公開 API 或官方統計，可重跑取得（目前只有動漫）。
- `estimated`：依公開報導推估，附來源連結與 ±5.5 區間（短劇／小說／電影）。
- `illustrative`：純介面示範，不得對外引用。

### 5. 驗證與可重現性

```bash
node scripts/fetch_anilist.mjs    # 1) 抓取（記錄 snapshotDate）
node scripts/build_dataset.mjs    # 2) 計分 + 合併
node scripts/validate_dataset.mjs # 3) 驗證（CI 必跑）
```

驗證器檢查：唯一 ID、五維範圍、`hitScore` 與加權結果一致、貢獻度加總、CI 包含分數、來源非空、雙語欄位完整、權重總和為 1。任何一項失敗，CI 會擋下 PR。

**可重現性**：`fetch_anilist.mjs` 記錄 `snapshotDate`；`build_dataset.mjs` 是純函式（同樣輸入 → 同樣輸出）；每次更新提交時 commit message 帶日期。研究者可用 commit hash 重算任何一版分數。

### 6. 反刷分與偏差控制

| 風險 | v0.1 做法 | v0.2 做法 |
|---|---|---|
| 刷分（小樣本高分） | 貝氏收縮（m=500） | + 評分分布熵、時間聚集度偵測 |
| 粉絲動員 | 口碑權重 < 熱度權重 | + 異常分布標記 |
| 地域偏差（AniList 英語圈） | 在方法論頁明示 | + 接入 Bangumi／MAL 交叉驗證 |
| 倖存者偏差 | 標明「非全集」 | + 納入未爆作品，報告 base rate |
| 題材紅利 | 破圈維度用同題材基準線 | + 題材歷史爆率（Bayesian prior） |

### 7. v0.2 路線（有資料才做）

1. **Cohort 正規化**：同媒介 × 同語言市場 × 上架月份 ±3 個月，用穩健 z 分數（median/MAD）取代固定常數，讓新舊作品公平比較。
2. **多源貝氏池化**：AniList + Bangumi + MAL 的分數做分層模型 `θ_i ~ N(μ, τ²)`，樣本少的來源自動降權。
3. **時間序列特徵**：`half_life`（衰減半衰期）、`late_share`（7 日後流量佔比）、`second_peak_ratio`（二次爆發）。
4. **Shapley 歸因**：用樹模型 + SHAP 檢查手拍權重是否偏離，輸出「內容層 vs 機制層」分解。
5. **敏感性分析**：權重 ±20% 擾動下的排名 Spearman ρ；ρ < 0.7 的維度要檢討。
6. **因果（僅在取得平台內部資料後）**：以推薦位灰度／檔期衝擊做 DiD 或工具變數，分離「投流」與「自然熱度」。

> 在沒有平台內部曝光與投放資料之前，**任何「劇情佔 X%」的宣稱都是不誠實的**。v0.1 的定位就是「可比較的相對熱度指數」。

### 8. 已知限制（必須公開）

1. 短劇／小說／電影沒有平台後台數據，分數是估算。
2. AniList 樣本偏英語圈；中文圈口碑可能被低估。
3. 收錄作品是「精選」而非全集，分母不完整。
4. 指數描述相關，不是因果。
5. 五維之間的相關性未完全去除（例如 reach 與 buzz 正相關）。

## English (full version)

### 1. Goals

Comparable across four media, explainable down to dimension weights, traceable to sources, reproducible from scripts, and honest when samples are thin. The index is explicitly **not** an absolute quality verdict and **not** a causal claim.

### 2. What the score means

`0–49` below cohort baseline · `50` baseline · `60–69` worth watching · `70–79` strong · `80–87` breakout · `88–100` phenomenon.
A 92 does not mean "12% better than 80"; it means "a stronger relative heat position among peers".

### 3. Model v0.1

**Dimensions**: reach, quality, buzz, momentum, crossover.

**Normalisation** (absolute 0–100 scale, constants are public calibration parameters):

```text
reach      = 100 · (log10(pop) − 3.3) / (5.9 − 3.3)
quality    = 100 · (WR − 58) / (90 − 58)
             WR = (n · S + 500 · 78) / (n + 500)        # Bayesian shrinkage, m = 500, C = 78
buzz       = 100 · (log10(n) − 3.4) / (5.9 − 3.4)
momentum   = 100 · (log10(trending + 1) − 1.3) / (2.7 − 1.3)
crossover  = 100 · (excess + 0.5) / (0.8 + 0.5)
             excess = log10(pop) − median(log10(pop) | primary genre)
```

**Aggregation and confidence**:

```text
Hit_raw = Σ_d  w[medium][d] · dim_d
Hit     = 50 + (Hit_raw − 50) × λ
λ       = max(0.93, n / (n + 600))        # anime only
CI90    = Hit ± δ,  δ = clamp(2160 / √n, 0.8, 6)   # anime
CI90    = Hit ± 5.5                                 # estimated records
```

**Weights**: short drama 26/14/22/20/18 (reach/quality/buzz/momentum/crossover), anime 28/26/16/15/15, novel 24/24/20/17/15, film 30/26/16/14/14.

**Decomposition** (the waterfall on every title page):

```text
contribution_d = w[medium][d] · (dim_d − 50) · λ
Σ contribution_d = Hit − 50
```

### 4. Dataset and data dictionary

`app/public/data/works.json` is the single source of truth. Each record carries: `id`, `medium`, bilingual `title`, `year`, `region`, `platform`, `genres`, bilingual `tags`, `episodes`, `synopsis`, `dims`, `hitScore`, `contributions`, `ci`, `confidence`, `heatCurve` or `scoreDistribution`, qualitative `drivers`, and `provenance` (`status` + `sources` + bilingual `note`).

Data status: `measured` (public API / official statistics, reproducible), `estimated` (public reporting, ±5.5 interval), `illustrative` (UI demo only, not citable).

### 5. Validation and reproducibility

Three commands: fetch → build → validate. The validator enforces unique IDs, dimension ranges, score/weight consistency, contribution sums, interval containment, non-empty sources, bilingual completeness and weight sums. CI blocks any PR that fails. The AniList fetch records a `snapshotDate`; the scoring script is deterministic, so any commit hash reproduces the exact scores.

### 6. Anti-gaming and bias

v0.1 relies on Bayesian shrinkage (m=500) and a genre-baseline crossover measure. v0.2 adds rating-distribution entropy, temporal burstiness, cross-source pooling (AniList + Bangumi + MAL), a survivorship-bias correction (include non-hits and report the base rate) and Shapley attribution with sensitivity analysis.

### 7. v0.2 roadmap

Cohort normalisation (medium × market × release month ±3), hierarchical Bayesian pooling across sources, time-series features (half-life, late share, second-peak ratio), Shapley decomposition of content vs. mechanism layers, and — only with platform-internal exposure data — DiD/IV causal designs.

### 8. Known limitations

Thin/absent platform-internal data for short dramas, novels and films; AniList's English-speaking bias; a curated rather than exhaustive catalogue; correlation not causation; residual correlation between dimensions.

## 9. 估算 SOP：短劇與華語編輯資料是怎麼算出來的

短劇、華語小說與電影沒有可公開取得平台後台數據的 API。我們**不手動填分數**，而是要求每筆資料提供「錨點（anchors）」，由 `scripts/build_dataset.mjs` 的固定函式換算成五維分數。因此任何人都能重算、審核、指出錯誤。

### 9.1 錨點 → 維度對照表

| 錨點 | 影響維度 | 換算方式（實作於 `estimateFromAnchors`） |
|---|---|---|
| `plays`（全網／平台播放量） | reach | `55 + 15·log10(plays/1e7 + 1)`：1 億 → 70、10 億 → 85、40 億 → 94 |
| `heatValue`（DataEye 熱力值，萬） | reach | `55 + 18·log10(heat/1000 + 1)`：2,000 萬 → 64、9,074 萬 → 72 |
| `dataeyeRank`（年度榜名次／100） | reach、buzz | reach = `50 + 47·(1 − (rank−1)/99)`；buzz = `45 + 50·(1 − (rank−1)/99)` |
| `criticScore`（豆瓣／媒體口碑，10 分制） | quality | `50 + (score − 6)·13`：8 分 → 76、9 分 → 89；無資料預設 70 |
| `awards`（獲獎數） | quality | 每項 +4，上限 +8 |
| `buzzLevel`（話題強度 0–1，人工判定） | buzz | `40 + 55·level` |
| `launchDate` | momentum | `18 + 70·exp(−距今天數/550)`（半衰期約 18 個月） |
| `genreBreakout`（是否跨題材出圈） | crossover | 是 → 84；否 → `55 + (reach − 60)·0.45` |

### 9.2 一筆實際例子：《家里家外》

| 步驟 | 輸入 | 輸出 |
|---|---|---|
| 錨點 | 上線 3 天紅果觀看破 10 億、正片有效播放 31.38 億、CMG 年度微短劇 | — |
| reach | `plays = 3.14e9` | `55 + 15·log10(315) = 92.5` → 92 |
| quality | 口碑 8.8、2 項獎 | `50 + 2.8×13 + 8 = 94.4` → 94（人工編輯值 88，採較保守值） |
| buzz | 48 小時話題破 5 億 | 人工編輯值 92 |
| momentum | 2025-03 上線 | 依上線時間衰減 |
| crossover | 年代家庭劇跨圈 | 94 |
| **破圈指數** | 權重 26/14/22/20/18 | **86.7** |

> 有 `dims` 的 14 筆早期資料是人工編輯值（方法標記為 `editorial`）；新增的 290 筆是錨點估算（`plays-anchored` / `heat-anchored` / `rank-anchored` / `baseline`）。**每筆的估算方法都寫在資料裡**，可逐筆檢視。

### 9.3 估算的誠實邊界

- 熱力值 ≠ 播放量 ≠ 分賬，三者不可互換；`anchorNote` 會記錄原始口徑。
- 同一部劇常有 2–3 種播放口徑（例如 40 億 vs 39.23 億），我們取報導中較保守或註明時點者。
- 只有「榜單名次」的資料，reach 以名次換算，**不代表實際播放量**；因此這類資料的 CI 較寬（±5.5）、信心為 low。
- 估算資料採用 `estimated` 狀態，**不得對外宣稱官方數據**。

## 10. 模型效能與診斷（可重跑）

執行 `node scripts/benchmark.mjs` 可得到以下數據（2026-11 快照，1,242 部）：

| 指標 | 數值 | 意義 |
|---|---|---|
| 資料集 | 1,242 部、2.1 MB、gzip 309 KB | 靜態 JSON 一次載入，不需資料庫 |
| JSON 解析 | 8.3 ms | 瀏覽器端可忽略 |
| 計分吞吐 | 0.16 ms／1,242 部（約 6,200 次/秒） | 模型計算不是瓶頸 |
| measured 比例 | 76.7%（952 部） | 動漫／小說／電影為實測，短劇為估算 |
| 分數中位數 | 50.6（p10 27.3、p90 68.7） | 分布合理，沒有過度集中 |
| 權重 ±20% 擾動排名穩定度 | Spearman ρ = 0.998（min 0.995） | 排名對權重不敏感，決策穩健 |
| 維度相關性 | reach×crossover 0.82、buzz×crossover 0.85 | **已知缺陷**：破圈維度與熱度高度重疊 |

**診斷結論**：
1. **計算效能完全不是問題**（毫秒級），真正的成本在資料取得與清理。
2. **排名穩定**：權重怎麼調，前 25 名幾乎不變——這是好事（可解釋），但也代表模型鑑別力有限。
3. **維度冗餘**是 v0.2 的首要修正項：crossover 目前大量由 reach 推導，應改成「非核心觀眾佔比」或「跨地區／跨平台擴散」的正交指標。
4. **預測效度尚未驗證**：需要每週快照累積 6–12 個月，才能回測「高分是否預測下月爆紅」（AUC / Precision@K）。這是 v0.3 的驗證計畫。
