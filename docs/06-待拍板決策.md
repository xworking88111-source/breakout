# 06 · 待拍板決策 / Decisions needed

## 中文

### D1. Repo 名稱與網址

- 選項：`breakout`、`breakout-index`、`poguo`（破圈拼音）、`hitrank`
- 影響：GitHub Pages 網址 `https://<user>.github.io/<repo>/`；品牌一致性
- **建議**：`breakout`（短、好記、與品牌一致）。若已被佔用，用 `breakout-index`。
- 需要你提供：GitHub 使用者名稱、最終 repo 名稱。

### D2. 授權

- 選項：程式碼 MIT / Apache-2.0；資料 CC BY 4.0 / CC BY-NC 4.0 / ODbL
- 影響：商業使用與衍生應用的自由度
- **建議**：程式碼 **MIT**（最寬鬆、最多人用）；衍生資料 **CC BY 4.0**（要求標註、允許商用）。AniList 上游資料另註明權利歸屬。

### D3. 是否把 AniList 快照放進 repo

- 選項 A：直接 commit `anime.json`（目前做法）→ 可離線重現、Pages 不依賴外部 API
- 選項 B：只放腳本，build 時才抓 → repo 較小，但建置依賴網路
- 風險：AniList 資料為社群貢獻，大量鏡像可能違反其條款精神
- **建議**：保留快照（目前 111 KB，屬合理引用範圍），並在 LICENSE 與 README 標明來源與非商業原型定位；上線前改為「只存衍生分數、不存原始欄位」。

### D4. 短劇資料要走到多深

- 選項 A：只做「編輯估算 + 公開報導」（目前，0 成本）
- 選項 B：接 DataEye／雲合付費資料（合規、精準，但違反「全免費」原則）
- 選項 C：低頻人工整理 App 內公開榜單（免費、合規邊界模糊）
- **建議**：A 為主，C 為輔（只記錄「排名變化」等衍生統計，不鏡像原始榜單）。B 列為未來商業化選項。

### D5. 第一版要覆蓋多少作品

- 現況：87 部（短劇 14、動漫 50、小說 11、電影 12）
- 目標：短劇 100+、動漫 500+、小說 100+、電影 100+
- **建議**：下一個里程碑先補短劇到 100 部（差異化最大），動漫用 AniList 一次可抓 500 部，成本極低。

### D6. 英文內容的深度

- 選項 A：介面與摘要雙語（目前）
- 選項 B：所有文檔全文雙語
- 選項 C：只做英文介面，文檔以中文為主
- **建議**：B 為目標，但分階段：先完成 02／03／06（核心），其餘先有英文摘要。

### D7. 商業模式

- **建議**：第一年完全免費、不接廣告；以「研究者引用 + 媒體報導」建立權威，第二年再談 B2B 資料服務。**不要賣排名**。

### D8. 是否納入「電影」與「歐美劇」

- 目前：電影納入、歐美劇未納入
- **建議**：電影保留（可與短劇對照），歐美劇 Phase 3 再談（資料源 TMDB 免費、但與現有客群關聯較弱）。

### D9. 資料更新頻率

- 動漫：每週（GitHub Actions 免費）
- 短劇：每月人工整理（避免合規風險）
- 電影：每月
- **建議**：照此節奏；在網站頁尾顯示「資料截止日」。

### D10. 要不要做使用者系統

- MVP：不需要（純靜態、無登入、無追蹤）
- 未來：若要「個人化推薦 / 收藏 / 提醒」，需要後端與資料庫（Supabase 免費層可起步）
- **建議**：Phase 2 再做；先用 localStorage 做「最近看過」即可。

## English

### D1. Repo name and URL

- Options: `breakout`, `breakout-index`, `poguo`, `hitrank`
- Impact: Pages URL `https://<user>.github.io/<repo>/` and brand consistency
- **Recommendation**: `breakout` (short, memorable); fall back to `breakout-index` if taken.
- Need from you: GitHub username and final repo name.

### D2. Licence

- Options: code MIT / Apache-2.0; data CC BY 4.0 / CC BY-NC 4.0 / ODbL
- Impact: freedom for commercial and derivative use
- **Recommendation**: code **MIT**; derived data **CC BY 4.0** (attribution, commercial use allowed). Note AniList's upstream rights separately.

### D3. Commit the AniList snapshot?

- A: commit `anime.json` (current) — reproducible offline, Pages independent of external API
- B: scripts only, fetch at build — smaller repo but network-dependent builds
- Risk: AniList data is community-contributed; large mirrors may conflict with its terms
- **Recommendation**: keep the snapshot (111 KB, reasonable quotation), state the source and prototype status in LICENSE/README; before launch, store derived scores only.

### D4. How deep should short-drama data go?

- A: editorial estimates + public reporting (current, zero cost)
- B: paid DataEye / Yunhe data (compliant, precise, but breaks the all-free rule)
- C: low-frequency manual capture of public in-app charts (free, legally grey)
- **Recommendation**: A primary, C secondary (store derived statistics such as rank changes, never mirror raw charts). Keep B as a future commercial option.

### D5. Catalogue size for v1

- Current: 87 titles (14 short dramas, 50 anime, 11 novels, 12 films)
- Target: 100+ short dramas, 500+ anime, 100+ novels, 100+ films
- **Recommendation**: next milestone = 100 short dramas (biggest differentiator); anime can jump to 500 via one AniList pull.

### D6. Depth of English content

- A: bilingual UI and summaries (current)
- B: full bilingual docs
- C: English UI only, docs mainly Chinese
- **Recommendation**: target B in stages — 02/03/06 first, English summaries elsewhere.

### D7. Business model

- **Recommendation**: fully free in year one, no ads; build authority through citations and media coverage; consider B2B data services in year two. **Never sell rankings.**

### D8. Include films? Western TV?

- Current: films yes, Western TV no
- **Recommendation**: keep films (useful contrast with short drama); defer Western TV to Phase 3 (TMDB is free but the audience overlap is weaker).

### D9. Update cadence

- Anime: weekly (free GitHub Actions)
- Short drama: monthly manual curation (limits legal risk)
- Films: monthly
- **Recommendation**: adopt this cadence and show "data as of" in the footer.

### D10. User accounts?

- MVP: no (static, no login, no tracking)
- Later: personalisation / watchlist / alerts would need a backend (Supabase free tier)
- **Recommendation**: defer to Phase 2; use localStorage for "recently viewed".
